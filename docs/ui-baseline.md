## 視覚言語（現状）

- **テーマ**: ダーク固定（`:root` に `--bg #12141c` 系 10 トークン、`color-scheme: dark`）。ベンチマークアプリの配色をそのまま継承
- **フォント**: システム（-apple-system / Hiragino Sans / Noto Sans JP）13px。ノードラベル 13 / sub 12 / small 11
- **ノード種別の色**（`src/flow/theme.ts` `KIND_COLOR`）: start 緑 / end 赤 / task 青 / decision 黄 / group 灰青
- **グループ**: 破線枠 + 「▼ 中を見る（N 件）」バッジ
- **リンク種別**: normal 実線 / exception 破線 `6 4` 赤系 / loopback 破線 `3 3` 黄系。ラベル（「不備あり」「NG」「4 件重複」等）は線上に小さく
- **ボタン**: 角丸 6px、`data-active` で accent 塗り。primary は「編集」「閲覧」の切替に使用

## 現状で気になる点（改善候補のメモ。方針決定前の観察）

- 情報の出し方
  - キャンバス左上の 1 行ヒント（「トップ 破線の箱＝中身のあるグループ…」）と左下の hint-bubble が二重に説明している
  - 「上へ」「中へ ▾」がパンくずと分かれており、現在地と移動手段の関係が視覚的に弱い
  - ⚙ に表示モードごとの設定（上位階層 / 左ペイン / 抽象度）が条件付きで出るため、何がなぜ出ているか分かりにくい
- 視覚言語
  - グループ（破線）と task（実線）の差が線種だけで、遠目で判別しづらい
  - exception / loopback のラベルが小さく、線の交差部で読めない（スクショの「不備あり」「4 件重複」）
  - ダーク固定。資料・共有用途ではライトテーマが要る可能性
- 空間の使い方
  - 3 階層サンプルのトップは横一列 6 ノードで縦が余る（レイアウト折り返しは効くが、この規模では発火しない）
  - DocPanel はオーバーレイでフローを隠す。split との併用時に窮屈
- 操作
  - 「潜る」がダブルクリック or バッジ、「戻る」がツールバーのみ。キャンバス上に戻る手段がない（`blank:dbclick` が無い制約）
  - nested のグループにホバー演出が付けられない（LogicFlow の制約。既知）
- 編集モード
  - JSON パネルが真実源の直接編集で、フロー構造を UI から変える手段は無い（POC スコープ外。UI 最適化でも手を出すか要判断）
