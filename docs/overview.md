# 概要

作成: 2026-09-15（`/hirai-lite:init` のヒアリングより）

## ゴール

業務フローの**構造定義（JSON）と描画**を React コンポーネント `FlowViewer` として npm パッケージ `@thirai-classlab/flow-viewer` にまとめ、別プロダクトに組み込めるようにする。その過程で、POC で実証済みの「具体⇔抽象を行き来する 3 表示モード」を、**業務設計者・管理者が全体構造を迷わず読める**見た目と触り方に仕上げる。

## 背景

- POC `~/work/雑務/flow-viewer/`（2026-08-27〜28）で 58 ライブラリ調査 → 11 ライブラリ実機比較 → LogicFlow 採用 → 階層アルゴリズムの検証（32 テストケース、面積比の総当たり実測）まで済んでいる
- POC の UI はベンチマークアプリのダークテーマ・ツールバーをそのまま継承しており、読む人向けには作られていない（`ui-baseline.md`）
- POC は比較実験の基準として凍結し、本リポジトリで UI とパッケージ化を進める
- 組み込み先（ホスト）は React 製の別プロダクト。ホストが Toolbar・パンくず・設定 UI を持ち、本パッケージはキャンバスだけを提供する

## スコープ

### 作るもの

- `FlowViewer` コンポーネント: キャンバス（ノード・エッジ・階層移動）+ 手順書パネル（読み取り専用）
- `FlowDoc` 型と `validateFlowDoc()`（JSON を境界で検証）
- ライト既定 + ダークのテーマ。CSS 変数トークンでホストから上書き可能。`style.css` は別ファイル
- 見た目の最適化（優先順）: 1. 視覚言語 → 2. キャンバス内の情報の出し方 → 3. 空間の使い方 → 4. 操作の発見性 → 5. レスポンシブ
- 品質ゲート: vitest（`src/lib/flow` の 32 ケース回帰）+ eslint
- 匿名化した実データのサンプル 1〜2 本

### 作らないもの

| 作らない | 理由 | 記録 |

| Toolbar / パンくず / 設定ポップオーバー | ホスト側が作る | — |
| 印刷 CSS / PNG・SVG・PDF 書き出し | 今回は何もしないと決めた | `tasks/parking-lot.md` |
| 編集モードの改修、UI からのフロー構造編集 | 機能追加に当たる。JSON 編集と 32 ケース切替は壊さない | `tasks/parking-lot.md` |

## ドメイン用語

| 用語 | 意味 |
|---|---|
| 業務フロー / `FlowDoc` | 真実源の JSON。`src/flow/schema.ts` が型を定義する |
| ノード種別 | `start` / `end` / `task` / `decision` / `group`（中に子フローを持つ） |
| リンク種別 | `normal`（実線）/ `exception`（例外遷移、破線・赤系）/ `loopback`（差し戻し、破線・黄系） |
| 階層 | group の中に子フローがある入れ子構造。深さ 1〜10 を想定 |
| 潜る / 戻る / 畳む | group の中へ入る / 上位階層へ出る / group を閉じて 1 ノードとして見せる |
| 表示モード | `drilldown`（1 画面 1 階層、既定）/ `split`（左に経路の入れ子、右に現在階層）/ `nested`（全階層を一度に描く） |
| 上位を表示 | drilldown で上位階層を薄く同時表示するフォーカス+コンテキスト（既定 ON） |
| `nestPath` / 抽象度 | split の左ペインの入れ子経路 / nested で一括して畳む深さ |
| 手順書（doc） | ノードに付く Markdown。DocPanel に表示する |
| パンくず | 現在地の階層経路。ホストが描く（`onPathChange` で受け取る） |
| ホスト | 本パッケージを組み込む別プロダクト |
| デモ | `src/demo/`。動作確認用のシェル UI（Toolbar / SidePanel / JsonPanel / InfoPanel / 32 ケース選択） |
