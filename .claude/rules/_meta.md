# ルール追加のルール

1. **二度目で書く**: 事故 2 回目で初めてルール化する。1 回目は事故記録 (`docs/rules-reference/incidents.md`) に 1 行記録して終える
2. **既定は T1**: 新規ルールは `paths:` 付きで置く。T0 にするには「全作業に例外なく効く」ことの立証が要る
3. **予算制**: T0 合計は警告 6,000 tokens / 上限 10,000 tokens の 2 段階。6,000 超で `tests/smoke.sh` case 4 が警告を出し（PASS のまま。余裕があるうちに降格候補を決める）、10,000 超で FAIL する。10,000 超のときは既存 1 件を T1/T2 へ降格するまで追加しない。上限は「入れてよい量」ではない — 条 2 のとおり新規は T1 が既定で、T0 には立証が要る
4. **1 ルール 1 事象・3 行以内**: 3 行で書けないものはルールでなく設計課題として扱う
5. **機械強制は不可逆操作のみ**: `settings.json` の `deny` / `ask` と hook で止めてよいのは「間違えたら戻せない」操作だけ。本条が禁じているのは**止める**仕組みなので、context を注ぐだけの hook（reminder / 表示）は対象外
6. **失効条件を必ず書く**: 全ルールに「いつ消せるか」を 1 行併記する
7. **パイプラインを通す**: 追加は `/add-rule` の 6 工程（分類 → 重複検査 → 層決定 → 記述最適化 → 予算 → ロード検証）を全て通す
8. **追加は承認必須**: AI は単独でルールを追加しない。提案 → ユーザー承認 → 配置。削除は承認不要。四半期点検で発火 0 のルールは削除する
9. **無い保証を書かない**: 機械強制が存在しない事項を「BLOCK する」「禁止する」と書かない。止める仕組み（`settings.json` の `deny` / `ask`、hook、smoke）がある事項だけ強制の語で書き、それ以外は指針として書く。前身のハーネスは docs に「BLOCK」と書きながら実際には止まらない状態を作り、AI が存在しない制約に萎縮する帰結を招いた

## 層

| 層 | 場所 | ロード |
|---|---|---|
| T0 | `CLAUDE.md` / `.claude/rules/_meta.md` / `.claude/rules/core.md` | 毎セッション常時（合計 警告 6,000 / 上限 10,000 tokens） |
| T1 | `.claude/rules/<domain>.md`（`paths:` あり） | 該当ファイルを触った時（1 file 2,000 tokens） |
| T2 | `docs/rules-reference/**` | AI が明示 Read した時のみ |
| T3 | `.claude/rules-archive/**` | ロードしない（失効ルールの履歴保持） |

## 数の予算

条 3 が「読む量」なら、こちらは**部品の数**。`tests/smoke.sh` case 6 が数え、超えたら FAIL する。

| 部品 | 上限 | 数え方 |
|---|---|---|
| hook | 5 | `hooks/*.sh` |
| command | 12 | `commands/*.md` |
| skill | 3 | `skills/*/SKILL.md` |
| smoke case | 10 | `tests/smoke.sh` の `case_N()` |

skill は本体こそ呼ばれた時だけ読まれるが、**`name` と `description` は常に載る**（1 件 50 tokens 前後）。上限に達したら 1 件外すまで足さない。

T2 は `.claude/rules/` の外に置く。`rules/` 配下は再帰的に発見されるため、`paths:` を書き忘れた瞬間に T0 へ昇格する事故を物理配置で防ぐ。T0 から T2 へのポインタは張らない（ポインタは T1 から張る）。

## 記述テンプレート

```markdown
- **<短い名前>**: <規範を肯定形で 1 行> ／ 例: <具体例 1 つ> ／ 失効: <いつ消せるか>
```

| 規則 | 悪い例 → 良い例 |
|---|---|
| 肯定形で書く | 「main を直接編集しない」→「main への変更は feature branch と PR 経由で行う」 |
| 判定可能な条件にする | 「適切な粒度でコミット」→「1 commit = 1 機能または 1 修正。テストが通る状態を保つ」 |
| 具体例は 1 つだけ | 0 だと解釈がぶれ、2 つ以上は冗長 |
| 主語を明示 | 「メインエージェントは」「サブエージェントは」で書き出す |

**禁止語彙**: `適切に` / `必要に応じて` / `可能な限り` / `十分に` / `慎重に` — 判定不能なため、具体的な条件・数値・コマンドに置き換える。

**`@import` は使わない**: CLAUDE.md 展開時に常時展開されるため context 削減効果がゼロで、純増になる。
