# 共通行動規範

全作業に例外なく効く規範のみを置く。特定の作業だけに効くものは T1（`paths:` 付き）へ。

- **完了の定義**: メインエージェントは、commit 前に build・test・lint を通す ／ 例: `npm run build && npm test && npm run lint` ／ 失効: CI が必ず同等の検査で落ちる構成になったら
- **commit 粒度**: メインエージェントは、1 commit = 1 機能または 1 修正で切り、各 commit を単体でテストが通る状態に保つ ／ 例: 実装と無関係な整形は別 commit にする ／ 失効: なし
- **承認が要る操作**: メインエージェントは、main への push / PR merge / 本番 deploy / DB migration / secrets 操作の前にユーザー承認を取る ／ 例: `git push origin main` は提案して止まる（`settings.json` の `ask` でも止まる） ／ 失効: なし
- **`loop`（自動で進む）のとき**: メインエージェントは、`mode.yml` が `loop` のとき確認を求めず作業を続ける。
  止まるのは 3 つ — ユーザーの停止指示 / タスク完了 / 続けられないエラー。
  新しい設計の追加・決めた内容の変更・元に戻せない操作は、`loop` でも承認を取る ／ 例: 実装中の方式選択は自律、新しい設計メモの起案は承認 ／ 失効: なし
- **設計の起点**: メインエージェントは、新機能を `docs/draft/` に起こし、承認後に台帳へ登録する ／ 例: `docs/draft/rate-limit.md` を承認 → 台帳に 1 行追加 ／ 失効: なし
- **事実で答える**: メインエージェントとサブエージェントは、ファイル・コマンド結果・外部仕様を述べるとき根拠を併記する。
  ファイルは `path:line`、コマンドは実行したコマンドと exit code、外部仕様は URL。
  根拠を示せないときは「未検証」と明記する ／ 例: 「9 case PASS（`bash tests/smoke.sh`、exit 0）」 ／ 失効: なし
- **宣言と実体を突き合わせる**: メインエージェントは、設定やマニフェストを変えたら、反映された件数・値を実測して期待値と比べる ／ 例: `claude plugin details <name>` の登録件数をリポジトリ内の実ファイル数と突き合わせる ／ 失効: なし
- **テストは壊して確かめる**: メインエージェントは、新しい検査を足したら、対象を故意に壊して FAIL することを確認してから採用する ／ 例: `paths:` を 1 行消したコピーで層違反検出が FAIL するか見る ／ 失効: なし
- **同種の欠陥を横に探す**: メインエージェントは、1 箇所直したら同じ原因の箇所を grep で全部洗い、同じ commit で直す ／ 例: 場所の決め打ちを 1 コマンドで直したら、残る解決経路とコマンドも同時に直す ／ 失効: なし
- **ルール追加の窓口**: メインエージェントは、新しい規範を思いついたら `_meta.md` のパイプラインを通す ／ 例: `/add-rule "完了 commit に台帳を含める"` ／ 失効: なし
- **承認は判断材料つきで求める**: メインエージェントは、承認を求めるとき「何をしたいか / なぜ / しないとどうなる / トレードオフ / どうやるか」の 5 点を本文に示す。**文面は全文を見せ、増減は数字で出す** ／ 例: 追加する行の全文と 「T0 4,231 → 4,300 tokens」 ／ 失効: なし
- **作業の起点は台帳**: メインエージェントは、作業前に台帳 (`docs/tasks/list.md`、無ければ `/new-task` が作る) を Read し、着手する task の status を 進行中 に更新する ／ 例: `/start-task 3` ／ 失効: 台帳を廃止したとき
- **重い作業は委譲する**: メインエージェントは、複数ファイルにまたがる調査・実装・検証を subagent へ `run_in_background: true` で委譲し、待機中も別の作業を進める ／ 例: 実装を 4 分割して subagent に配る ／ 失効: なし
- **同時起動は 2 件まで**: メインエージェントは、同時に走らせる subagent を 2 件までにし、完了通知を受けてから次を起動する ／ 例: 4 件なら 2 件ずつ 2 回に分ける ／ 失効: 同時 4 件以上が安定して完走するようになったとき
- **レビューは並列で立てる**: メインエージェントは、成果物ができた時点で観点の異なる reviewer を 2 本以上並列起動する ／ 例: `code-reviewer` と `security-reviewer` を同時に走らせる ／ 失効: なし
- **判断を求められたら止まる**: サブエージェントが「要判断」を返したとき、メインエージェントは user に選択肢を出して指示を待つ ／ 例: 「案 A / 案 B / 推奨は A」と提示する ／ 失効: なし
